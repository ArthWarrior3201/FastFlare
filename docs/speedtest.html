Speed test, by provider and city

Visitors pick a provider, then a city that provider has a server in, and run a test against that exact server. You get download, upload, latency, jitter and packet loss, plus live throughput data for graphs.

Open the live speed test

How the provider and city list works

A speed test is only meaningful against a real server, so each location is a FastFlare node you run. Start the same server on a VM at each provider and city, and tell it where it is:

# On a VM in AWS Frankfurt
FF_PROVIDER="AWS" FF_CITY="Frankfurt" FF_COUNTRY="DE" \
FF_PUBLIC_URL="https://fra.speed.example.com" node src/server.js

Then pick one node to be the registry and list the others in its config/servers.json:

[
  { "provider": "AWS",     "city": "Frankfurt", "country": "DE", "url": "https://fra.speed.example.com" },
  { "provider": "AWS",     "city": "Mumbai",    "country": "IN", "url": "https://bom.speed.example.com" },
  { "provider": "Hetzner", "city": "Helsinki",  "country": "FI", "url": "https://hel.speed.example.com" },
  { "provider": "Google Cloud", "city": "Singapore", "country": "SG", "url": "https://sin.speed.example.com" }
]

The registry's own FF_PROVIDER / FF_CITY are listed too. The city dropdown only shows cities where the chosen provider has a node, because it is built from this list. Nodes need HTTPS if the page using them is HTTPS, and every node sends CORS headers so the browser can talk to any of them.

Public nodes serve test traffic to any visitor. Each request is capped by FF_MAX_BYTES (default 100 MB); add a bandwidth limit at your provider if you want a monthly ceiling.

Embed it in your app

<script src="https://YOUR-REGISTRY-HOST/fastflare-speedtest.js"></script>

<select id="provider"></select> <select id="city"></select> <button id="start">Start</button>
<pre id="out"></pre>

<script>
const st = new FastFlareSpeedTest({ api: 'https://YOUR-REGISTRY-HOST' });
const $ = (id) => document.getElementById(id);

st.loadServers().then(() => {
  $('provider').innerHTML = st.providers().map(p => `<option>${p}</option>`).join('');
  fillCities();
});
function fillCities() {   // only cities the selected provider is available in
  $('city').innerHTML = st.cities($('provider').value).map(s => `<option value="${s.id}">${s.city}</option>`).join('');
}
$('provider').onchange = fillCities;

$('start').onclick = async () => {
  const result = await st.run({
    serverId: $('city').value,
    onPhase: (p) => ($('out').textContent = 'Testing: ' + p),
    onProgress: ({ phase, mbps }) => ($('out').textContent = `${phase}: ${mbps.toFixed(1)} Mbps`),
  });
  $('out').textContent =
    `Download ${result.download.mbps.toFixed(1)} Mbps\n` +
    `Upload   ${result.upload.mbps.toFixed(1)} Mbps\n` +
    `Latency  ${result.latency.median.toFixed(1)} ms (jitter ${result.latency.jitter.toFixed(1)} ms, loss ${(result.latency.loss * 100).toFixed(0)}%)`;
};
</script>

API

new FastFlareSpeedTest(options)

OptionDefaultMeaning
api(required)URL of the registry node.
registryapi + '/speed/servers'Full URL of the server list, if you host it elsewhere.
pings20Number of latency samples.
downloadPlan, uploadPlanstaged 100 KB to 50 MBArrays of {bytes, count, parallel} stages. Stages that would take over maxStageSeconds (10) are skipped on slow links.

Methods

loadServers()Fetches the registry. Resolves the server list.
providers()Sorted provider names.
cities(provider)Servers of that provider (id, provider, city, country, url).
run({serverId | server, signal, onPhase, onProgress, onPing})Latency, then download, then upload. Pass an AbortSignal to cancel.

Result

{
  server: { id, provider, city, country, url },
  latency:  { min, median, mean, p90, max, jitter, loss, samples: [ms, ...] },
  download: { mbps, stages: [{ bytes, count, parallel, mbps, ms }], series: [{ t, mbps }, ...] },
  upload:   { mbps, stages: [...], series: [...] },
  startedAt, durationMs
}

mbps is the 90th percentile across the 1 MB and larger stages. Each stage subtracts one median round trip so distance doesn't pretend to be a slow line. jitter is the mean absolute difference between consecutive pings. series is throughput over time (about every 100 ms) for drawing graphs; the live page draws it on a canvas.

Server endpoints

GET /speed/serversThe provider/city registry.
GET /speed/pingEmpty reply, for latency.
GET /speed/down?bytes=NStreams N random bytes.
POST /speed/upConsumes the body, returns {bytes, ms}.
GET /speed/infoThis node's description and the caller's IP.
