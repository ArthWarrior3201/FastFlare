Host Your Own CDN

Run the FastFlare CDN on your own server. Files are encrypted on upload and stored on the server or a GitHub branch; downloads are decrypted and delivered by Vercel's edge network, close to every visitor.

Where Files Are Stored

GitHubFiles from 5 MB to 1 GB, stored on the cdn branch as encrypted parts of about 44 MB each.
Your ServerSmall files up to 5 MB (cached at the edge), files over 1 GB, anything the owner sends there on purpose, and everything when GitHub is full or not set up.

Every file is encrypted with AES-256-GCM in 1 MB segments and split into .ffencrypted parts of about 44 MB. Storage only ever holds encrypted parts with random names. The server keeps a fingerprint of each upload's key, never the key itself.

Smart Routing

Every download link is the same, and FastFlare picks the fastest path for the file behind it:

FileRouteWhy
Small (up to 25 MB)Vercel edgeServed from the edge node nearest the visitor, and cached there.
Normal (25 to 500 MB)Your server, directlyOne steady stream, with resuming. No time limit.
Extra large (over 500 MB)Chunked downloadThe browser opens a download page that fetches the file in 32 MB pieces, four at a time, through the edge, and joins them on the visitor's device. Each piece finishes well inside Vercel's 300-second limit.

Download tools such as curl and download managers always get the file directly, and a request for part of a file (video seeking, resuming) is answered wherever it arrives. Add &route=edge, &route=native or &route=chunked to a link to force a route. Change the sizes with FF_ROUTE_SMALL_MB and FF_ROUTE_XL_MB, set to the same values on the server and on Vercel.

Chunked downloads save straight to disk in Chrome and Edge. Other browsers join the pieces in memory for files up to 2 GB; above that, the page offers the standard download.

Setup

The CDN runs on any FastFlare server (see the install guide). With nothing else configured, files are stored on the server itself. GitHub storage and Vercel delivery are optional and can be added at any time.

  1. Choose an owner token (for you only) Visitors upload with the "I'm not a robot" check and per-network limits. The owner token skips both, lets you choose where a file is stored, and is needed to delete files and see usage. Keep it private. 
    echo "FF_CDN_TOKEN=$(openssl rand -hex 24)" | sudo tee -a /etc/fastflare.env
  2. GitHub (large files) On GitHub, open Settings → Developer settings → Fine-grained tokens → Generate new token. Give it access to the FastFlare repository only, with Contents: Read and write. Then add it: 
    echo "FF_CDN_GITHUB_TOKEN=github_pat_YOUR_TOKEN" | sudo tee -a /etc/fastflare.env
    Parts are committed to the cdn branch. To use another repository or branch, set FF_CDN_GITHUB_REPO=owner/name and FF_CDN_GITHUB_BRANCH.
  3. Vercel (fast downloads) Sign in at vercel.com with GitHub and choose Add New → Project. Import the FastFlare repository, set Root Directory to vercel, and under Environment Variables add FF_ORIGIN = https://YOUR-SERVER. Press Deploy. Copy the address Vercel gives you and tell the server about it, so upload links use it: 
    echo "FF_CDN_EDGE_URL=https://YOUR-PROJECT.vercel.app" | sudo tee -a /etc/fastflare.env
  4. Restart 
    sudo systemctl restart fastflare
    Check what is set up with GET /cdn/status, or upload a test file above.

Owner API

RequestWhat it does
PUT /cdn/upload?name=FILEUpload one file (the request body). The first file of a batch needs the owner token (Authorization: Bearer TOKEN) or a FastFlare human-check token (X-FF-Captcha). It returns an upload ticket; send it as X-FF-Ticket with the rest of the batch. Add &done=1 to the last file to receive the key. The owner can add &tier=vm|github.
POST /cdn/finish with X-FF-TicketEnds a batch and returns the key and link.
PUT /cdn/upload?name=FILE&bundle=ID with X-FF-KeyAdds a file to an existing upload.
DELETE /cdn/ID[/NAME]Removes a file or a whole upload. Owner token required.
GET /cdn/status, GET /cdn/bundlesSpace used per store, and every upload. Owner token required.

Upload from PowerShell:

Invoke-RestMethod -Method Put -InFile .\setup.exe -Headers @{ Authorization = "Bearer YOUR_TOKEN" } `
  -Uri "https://YOUR-SERVER/cdn/upload?name=setup.exe&done=1"

From macOS or Linux:

curl -T setup.exe -H "Authorization: Bearer YOUR_TOKEN" "https://YOUR-SERVER/cdn/upload?name=setup.exe&done=1"

Limits Worth Knowing

  • GitHub asks that repositories stay under 5 GB. Deleting a file removes it from the cdn branch, but it stays in the branch history and still counts. Cloning the repository normally also fetches this branch: use git clone --single-branch for the code only.
  • Vercel's free plan includes 100 GB of downloads a month, and an edge response can stream for up to 300 seconds, which is why large files go in chunks. Files stored on your server still travel from it to the edge, so for the fastest chunked downloads keep large files on GitHub.
  • Small single files opened by a ?key= link are cached on Vercel's network for a day, so repeat downloads do not touch your server at all.
