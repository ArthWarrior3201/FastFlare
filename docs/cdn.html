      How It Works

      1. Your files are encrypted as they arrive, with a key made just for this upload, and split into tamper-proof parts.
      2. When every file is in, you get a link, an upload ID and the key. The service keeps only a fingerprint of the key: enough to check it, never enough to open your files.
      3. When someone opens the link, the nearest delivery location checks the key, decrypts the file on the fly and verifies every part. A wrong key gets nothing, and a damaged file is refused rather than delivered.
      4. Small files open instantly from a nearby cache. Very large files download in several parts at once and are joined on the visitor's device.

      Questions

      I lost my key. Can it be reset?

      No. The key is never stored, so nobody can recover it. That is what keeps your files private. Use Save Key File or a password manager.

      Who can access uploaded files?

      Only people and systems you give the link or key to. Storage holds encrypted parts with random names, and the service itself cannot decrypt them without your key.

      What are the limits?

      Up to 1 GB per file, and up to 50 files or 2 GB per network each day. Very large files download best in Chrome or Edge, which save them straight to disk.

      Can files be served directly from a website or app?

      Yes. A link to a single image, video, audio file or PDF opens directly in the browser, so it works in <img> and <video> tags. Add &download=1 to make it download instead.

      RequestReturns
      GET /cdn/ID?key=KEYEvery file in the upload: a single file as itself, several as a .zip.
      GET /cdn/ID/NAME?key=KEYOne file, with Range support for resuming and seeking.
      GET /cdn/ID?key=KEY&files=a.png,b.cssOnly the listed files.
      GET /cdn/ID?key=KEY&list=1The file list as JSON.

      The key can also be sent as an X-FF-Key header, which keeps it out of URLs and logs. To run this service on your own servers, see Host Your Own CDN.
