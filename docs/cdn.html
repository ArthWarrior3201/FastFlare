Encrypted File Delivery Across Three Stores

Upload once. FastFlare encrypts every file, splits it into parts, and spreads them across your server, Supabase and GitHub. Downloads run on Vercel's edge network, close to every visitor, and need the key you were given at upload.

How It Works

SupabaseSmall files up to 5 MB: logos, icons, images, stylesheets. Fast, and cached on the server so popular files are fetched once.
GitHubFiles from 5 MB to 1 GB, stored on the cdn branch as encrypted parts of about 44 MB each.
Your ServerMain files: anything over 1 GB, anything you send there on purpose, and everything else when the other stores are full or not set up.
  1. You upload through your FastFlare server. It encrypts each file with AES-256-GCM using a new random 256-bit key, in 1 MB segments that each carry their own tamper check.
  2. The encrypted parts (.ffencrypted) go to the store that suits the file's size. Supabase and GitHub only ever hold encrypted data with meaningless names.
  3. When every file is in, you get the bundle ID and the key, once. No key is needed to upload, and anyone can upload after the "I'm not a robot" check. The server keeps only a fingerprint of the key, so it can check requests but cannot decrypt anything on its own.
  4. A download goes to the Vercel edge node nearest the visitor. The edge asks your server whether the key is right; if it is, the server hands back short-lived links to the encrypted parts. The edge fetches them straight from Supabase and GitHub, decrypts and checks every segment, and streams the file. A wrong key gets nothing, and an altered part stops the download.
  5. Your server only checks keys and hands out links, so its own connection is no longer the limit for files stored on Supabase and GitHub.
About the key. AES-256 is the standard for encrypting files, and it is far stronger than a 2048-bit RSA key. Lose the key and the files cannot be recovered by anyone, including you. Save it in a password manager or on your own server.

Smart Routing

Every download link is the same, and FastFlare picks the fastest path for the file behind it:

FileRouteWhy
Small (up to 25 MB)Vercel edgeServed from the edge node nearest the visitor, and cached there.
Normal (25 to 500 MB)Your server, directlyOne steady stream, with resuming. No time limit.
Extra large (over 500 MB)Chunked downloadThe browser opens a download page that fetches the file in 32 MB pieces, four at a time, through the edge, and joins them on the visitor's device. Each piece finishes well inside Vercel's 300-second limit.

Download tools such as curl and download managers always get the file directly, and a request for part of a file (video seeking, resuming) is answered wherever it arrives. Add &route=edge, &route=native or &route=chunked to a link to force a route. Change the sizes with FF_ROUTE_SMALL_MB and FF_ROUTE_XL_MB, set to the same values on the server and on Vercel.

Chunked downloads save straight to disk in Chrome and Edge. Other browsers join the pieces in memory for files up to 2 GB; above that, the page offers the standard download.

      Links and API

      Share links on your Vercel address, for example https://your-project.vercel.app/cdn/BUNDLE?key=KEY. The same paths also work directly on your server. Every link carries the key, either as ?key= or as an X-FF-Key header. Use the header from your own code when the key should not appear in a URL.

      RequestReturns
      GET /cdn/BUNDLE?key=KEYEvery file: one file as itself, several as a .zip.
      GET /cdn/BUNDLE?key=KEY&files=logo.png,app.cssOnly those files.
      GET /cdn/BUNDLE/logo.png?key=KEYOne file. Images, audio, video and PDFs open in the browser, so this works in <img src>. Supports Range for resuming and seeking. Add &download=1 to force a download.
      GET /cdn/BUNDLE?key=KEY&list=1File names, sizes and stores as JSON.
      PUT /cdn/upload?name=FILEUpload one file (the request body). The first file needs a FastFlare human-check token (X-FF-Captcha) or the owner token (Authorization: Bearer TOKEN). It returns the bundle and an upload ticket; send the ticket as X-FF-Ticket with the other files of the batch. Add &done=1 to the last file to get the key straight away. The owner can also add &tier=vm|supabase|github.
      POST /cdn/finish with X-FF-TicketEnds the batch and returns the decryption key and the download link.
      PUT /cdn/upload?name=FILE&bundle=ID with X-FF-KeyAdd a file to a bundle you already have the key for.
      DELETE /cdn/BUNDLE[/FILE]Remove a file or the whole bundle. Needs the upload token.
      GET /cdn/status, GET /cdn/bundlesSpace used per store, and your bundles. Need the upload token.

      The owner can upload from scripts. From PowerShell:

      Invoke-RestMethod -Method Put -InFile .\setup.exe -Headers @{ Authorization = "Bearer YOUR_TOKEN" } `
  -Uri "https://129-225-87-247.sslip.io/cdn/upload?name=setup.exe&done=1"

      From macOS or Linux:

      curl -T setup.exe -H "Authorization: Bearer YOUR_TOKEN" "https://129-225-87-247.sslip.io/cdn/upload?name=setup.exe&done=1"

      Set Up the Stores

      The CDN works with just your server. Supabase and GitHub are optional: until they are set up, files go to your server.

      1. Choose an owner token (for you only) Visitors upload with the human check and per-network limits. Your owner token skips both and lets you choose the store and delete files. Keep it private. 
        echo "FF_CDN_TOKEN=$(openssl rand -hex 24)" | sudo tee -a /etc/fastflare.env
      2. Supabase (small files) Create a free project at supabase.com. In Storage, create a bucket named ffcdn and leave it private. In Project Settings → API Keys, copy the project URL and the secret (service role) key, then add them: 
        echo "FF_SUPABASE_URL=https://YOURPROJECT.supabase.co" | sudo tee -a /etc/fastflare.env
echo "FF_SUPABASE_KEY=YOUR_SECRET_KEY" | sudo tee -a /etc/fastflare.env
      3. GitHub (large files) On GitHub, open Settings → Developer settings → Fine-grained tokens → Generate new token. Give it access to the FastFlare repository only, with Contents: Read and write. Then add it: 
        echo "FF_CDN_GITHUB_TOKEN=github_pat_YOUR_TOKEN" | sudo tee -a /etc/fastflare.env
        Parts are committed to the cdn branch. To use another repository or branch, set FF_CDN_GITHUB_REPO=owner/name and FF_CDN_GITHUB_BRANCH.
      4. Vercel (fast downloads) Sign in at vercel.com with GitHub and choose Add New → Project. Import the FastFlare repository, set Root Directory to vercel, and under Environment Variables add FF_ORIGIN = https://129-225-87-247.sslip.io. Press Deploy. Copy the address Vercel gives you and tell the server about it, so upload links use it: 
        echo "FF_CDN_EDGE_URL=https://YOUR-PROJECT.vercel.app" | sudo tee -a /etc/fastflare.env
      5. Restart 
        sudo systemctl restart fastflare
        Check what is set up with GET /cdn/status, or upload a test file above.

      Limits Worth Knowing

      • Supabase's free plan allows 1 GB of storage, 50 MB per object and 5 GB of downloads a month. The server cache means each popular file is usually read from Supabase once.
      • GitHub asks that repositories stay under 5 GB. Deleting a file removes it from the cdn branch, but it stays in the branch history and still counts. Cloning the repository normally also fetches this branch: use git clone --single-branch for the code only.
      • Vercel's free plan includes 100 GB of downloads a month, and an edge response can stream for up to 300 seconds, which is why large files go in chunks. Files stored on your server still travel from it to the edge, so for the fastest chunked downloads keep large files on GitHub.
      • Small single files opened by a ?key= link are cached on Vercel's network for a day, so repeat downloads do not touch Supabase or your server at all.
