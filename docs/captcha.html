Bot protection, no picture puzzles

Add a widget to your form, verify one token on your server. Visitors see a one-line "Verified" badge, not a grid of crosswalks.

How it works

  1. The widget asks your FastFlare server for a signed challenge.
  2. The browser solves a small SHA-256 proof-of-work in Web Workers (a fraction of a second normally). Real people don't notice; running it thousands of times costs a bot farm real CPU.
  3. It also reports behaviour signals (pointer and keyboard activity, navigator.webdriver, and so on). Clean traffic passes. Odd traffic gets a harder proof-of-work. Obvious automation is rejected.
  4. The server returns a short-lived, single-use token. Your backend exchanges it at /captcha/siteverify.

Difficulty rises automatically for any network that requests many challenges per minute.

Be realistic about what this is. No CAPTCHA stops a determined attacker who is willing to pay. Proof-of-work and signals raise the cost of abuse and stop lazy scripts, scrapers and credential-stuffing at low effort, but the signals come from the client and can be forged. Pair it with rate limits on sensitive endpoints.

1 · Create site keys

Create config/sites.json on your FastFlare server (it is git-ignored). Use long random secrets.

{
  "ff_site_3f9a1c": {
    "secret": "REPLACE_WITH_openssl_rand_-hex_32",
    "origins": ["https://example.com", "https://www.example.com"]
  }
}

origins is optional. When set, only browsers on those origins can request challenges for that key. Without any config the server enables a public demo key, ff_demo_site / ff_demo_secret, for testing only.

2 · Add the widget to your page

<script src="https://YOUR-FASTFLARE-HOST/fastflare.js" async defer></script>

<form method="post" action="/signup">
  <input name="email" type="email" required>
  <div class="ff-captcha" data-sitekey="ff_site_3f9a1c"></div>
  <button>Sign up</button>
</form>

The widget adds a hidden field named ff-token to the form and keeps it fresh (tokens last two minutes, and the widget renews them). Because the script is loaded from your own FastFlare host, it knows where to talk to automatically. If you host fastflare.js elsewhere, add data-api="https://YOUR-FASTFLARE-HOST".

Options (data attributes or JS)

AttributeMeaning
data-sitekeyRequired. Your site key.
data-apiFastFlare server URL. Defaults to the origin fastflare.js was loaded from.
data-callbackName of a global function called with the token.
data-expired-callback, data-error-callbackNames of global functions.
data-themelight, dark or auto (default).
data-fieldHidden input name (default ff-token).
data-settleMilliseconds to wait for a sign of human interaction before submitting (default 1200).

Programmatic and invisible use

// Render into any element
const w = FastFlare.render('#box', { sitekey: 'ff_site_3f9a1c', theme: 'dark', callback: (t) => console.log(t) });
w.token();   // current token or null
w.reset();   // solve again

// No UI at all: get a token before calling your own API
const token = await FastFlare.execute({ sitekey: 'ff_site_3f9a1c', api: 'https://YOUR-FASTFLARE-HOST' });
await fetch('/api/comment', { method: 'POST', headers: { 'Content-Type': 'application/json' },
                              body: JSON.stringify({ text, 'ff-token': token }) });

3 · Verify on your server

Always verify server-side. A token in the browser proves nothing until your backend checks it. Tokens are single-use and expire after two minutes.

POST /captcha/siteverify with secret, response (the token) and optionally remoteip. JSON and form encoding both work, like reCAPTCHA.

// Node 18+
const r = await fetch('https://YOUR-FASTFLARE-HOST/captcha/siteverify', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ secret: process.env.FF_SECRET_KEY, response: req.body['ff-token'], remoteip: req.ip }),
});
const out = await r.json();           // { success: true, challenge_ts: "...", score: 0.9 }
if (!out.success) return res.status(400).send('Bot check failed');
# Python
import requests
out = requests.post("https://YOUR-FASTFLARE-HOST/captcha/siteverify",
    data={"secret": SECRET, "response": request.form["ff-token"], "remoteip": request.remote_addr}).json()
if not out["success"]:
    abort(400)
// PHP
$out = json_decode(file_get_contents('https://YOUR-FASTFLARE-HOST/captcha/siteverify', false, stream_context_create(['http' => [
  'method' => 'POST', 'header' => 'Content-Type: application/x-www-form-urlencoded',
  'content' => http_build_query(['secret' => $secret, 'response' => $_POST['ff-token'], 'remoteip' => $_SERVER['REMOTE_ADDR']]),
]])), true);
if (empty($out['success'])) { http_response_code(400); exit; }

Responses

{ "success": true, "challenge_ts": "2026-11-22T09:30:00.000Z", "score": 0.9 }
{ "success": false, "error-codes": ["timeout-or-duplicate"] }

Error codes: invalid-input-secret, invalid-input-response, timeout-or-duplicate, remoteip-mismatch. score is 0 to 1 (higher is more human-looking). Use it to decide whether to add your own extra checks on risky actions.

Server API reference

  

    
EndpointCalled byPurpose

    
POST /captcha/challenge {sitekey}BrowserReturns a signed proof-of-work challenge.

    
POST /captcha/verify {sitekey, challenge, nonce, signals, hp}BrowserChecks the proof and signals. Returns {ok, token}, {ok:false, retry:true, challenge} (step-up) or 403.

    
POST /captcha/siteverify {secret, response, remoteip?}Your backendValidates and consumes a token. Has no CORS headers on purpose, since it takes your secret.

  

  
Keep FF_SECRET stable and shared if you run several instances. Behind a proxy, set TRUST_PROXY=1.
