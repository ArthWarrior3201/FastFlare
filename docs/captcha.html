Bot Protection Without Picture Grids

Add a widget to your form, verify one token on your server. Visitors see a one-line "Verified" badge, not a grid of crosswalks.

How It Works

  1. The widget asks your FastFlare server for a signed challenge and solves a small SHA-256 proof-of-work in Web Workers. Difficulty rises for networks sending many requests.
  2. While that runs, it records the visitor's real pointer path. People accelerate, brake and wobble; scripts tend to move in straight lines at constant speed.
  3. Clear automation (webdriver, headless browsers, non-browser clients, a filled honeypot, impossible timings) is rejected outright.
  4. If everything looks human, the visitor is verified invisibly. If FastFlare is not sure, it shows a quick puzzle: slide a shape into the matching hole in a picture. The hole's position exists only in the picture, so a script calling the API cannot answer it blind. The drag itself is checked too.
  5. The result is a short-lived, single-use token. Your backend exchanges it at /captcha/siteverify.
Security notes. No CAPTCHA is absolute. Bots that read the puzzle with computer vision, or pay people to solve it remotely, can pass it. FastFlare limits the damage with per-network quotas and lock-outs, but you should also rate-limit the action the token protects (sign-up, login, checkout). The method field in siteverify tells you whether a token came from an invisible pass or a solved puzzle.

Limits per Network

Over a rolling 10 minutes, each network address gets FF_QUOTA_SOFT invisible verifications (default 1); after that every verification needs the puzzle. At FF_QUOTA_HARD tokens (default 8) it stops issuing them (429 too_many_tokens). Three failed puzzles lock the address out for the rest of the window (429 too_many_failures). Sites whose visitors share one address (mobile carriers, offices, campuses) may want higher numbers.

Fastest Way: Use the FastFlare Network

You do not need your own FastFlare server. Create a site key on the Quick Start page, run the small gate backend anywhere, and the FastFlare network decides for every visitor whether to let them through, challenge them or block them. Visitors who pass are sent to your redirect_to_if_pass page; everyone else is asked to try again.

The rest of this guide covers running your own FastFlare server and wiring the widget into an existing form.

1 · Create Site Keys

On the FastFlare network, use the Quick Start form. On your own server, create config/sites.json (it is git-ignored). Use long random secrets.

{
  "ff_site_3f9a1c": {
    "secret": "REPLACE_WITH_openssl_rand_-hex_32",
    "origins": ["https://example.com", "https://www.example.com"]
  }
}

origins is optional. When set, only browsers on those origins can request challenges for that key. Without any config the server enables a public demo key, ff_demo_site / ff_demo_secret, for testing only.

2 · Add the Widget to Your Page

<script src="https://YOUR-FASTFLARE-HOST/fastflare.js" async defer></script>

<form method="post" action="/signup">
  <input name="email" type="email" required>
  <div class="ff-captcha" data-sitekey="ff_site_3f9a1c"></div>
  <button>Sign up</button>
</form>

This shows an "I'm not a robot" box. While the page loads, the widget quietly prepares the proof-of-work, so when the visitor clicks, verification takes a moment. People who look human are verified on the spot; anyone FastFlare is unsure about gets the quick shape puzzle. The widget adds a hidden field named ff-token to the form. Tokens last two minutes; after that the box unchecks itself and the visitor clicks it again. Because the script is loaded from your own FastFlare host, it knows where to talk to automatically. If you host fastflare.js elsewhere, add data-api="https://YOUR-FASTFLARE-HOST".

Options (Data Attributes or JavaScript)

AttributeMeaning
data-sitekeyRequired. Your site key.
data-modecheckbox (default): verify when the visitor clicks "I'm not a robot". auto: start verifying as soon as the page loads, no click needed.
data-apiFastFlare server URL. Defaults to the origin fastflare.js was loaded from.
data-verifyYour backend endpoint. After a pass the widget posts {"token", "redirect"} there and waits for {"success": true, "redirect": "…"}. A failure shows "Could not verify, try again". See the Quick Start.
data-redirectThe redirect_to_if_pass address, used with data-verify. Your backend's answer can override it.
data-callbackName of a global function called with the token.
data-expired-callback, data-error-callbackNames of global functions.
data-themelight, dark or auto (default).
data-fieldHidden input name (default ff-token).
data-settleLongest wait, in milliseconds, for pointer movement before submitting (default 500 after a click, 3000 in auto mode). Visitors who do not move get the puzzle.

Programmatic and Invisible Use

// Render into any element
const w = FastFlare.render('#box', { sitekey: 'ff_site_3f9a1c', theme: 'dark', callback: (t) => console.log(t) });
w.token();   // current token or null
w.reset();   // solve again

// No UI at all: get a token before calling your own API
const token = await FastFlare.execute({ sitekey: 'ff_site_3f9a1c', api: 'https://YOUR-FASTFLARE-HOST' });
await fetch('/api/comment', { method: 'POST', headers: { 'Content-Type': 'application/json' },
                              body: JSON.stringify({ text, 'ff-token': token }) });

3 · Verify on Your Server

Always verify server-side. A token in the browser proves nothing until your backend checks it. Tokens are single-use and expire after two minutes.

POST /captcha/siteverify with secret, response (the token) and optionally remoteip. JSON and form encoding both work, like reCAPTCHA.

// Node 18+
const r = await fetch('https://YOUR-FASTFLARE-HOST/captcha/siteverify', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ secret: process.env.FF_SECRET_KEY, response: req.body['ff-token'], remoteip: req.ip }),
});
const out = await r.json();           // { success: true, challenge_ts: "...", score: 0.9 }
if (!out.success) return res.status(400).send('Bot check failed');
# Python
import requests
out = requests.post("https://YOUR-FASTFLARE-HOST/captcha/siteverify",
    data={"secret": SECRET, "response": request.form["ff-token"], "remoteip": request.remote_addr}).json()
if not out["success"]:
    abort(400)
// PHP
$out = json_decode(file_get_contents('https://YOUR-FASTFLARE-HOST/captcha/siteverify', false, stream_context_create(['http' => [
  'method' => 'POST', 'header' => 'Content-Type: application/x-www-form-urlencoded',
  'content' => http_build_query(['secret' => $secret, 'response' => $_POST['ff-token'], 'remoteip' => $_SERVER['REMOTE_ADDR']]),
]])), true);
if (empty($out['success'])) { http_response_code(400); exit; }

Responses

{ "success": true, "challenge_ts": "2026-11-22T09:30:00.000Z", "score": 0.9, "method": "invisible" }
{ "success": false, "error-codes": ["timeout-or-duplicate"] }

Error codes: invalid-input-secret, invalid-input-response, timeout-or-duplicate, remoteip-mismatch. score is 0 to 1 (higher is more human-looking). Use it to decide whether to add your own extra checks on risky actions.

Server API Reference

  

    
EndpointCalled byPurpose

    
POST /captcha/challenge {sitekey}BrowserReturns a signed proof-of-work challenge.

    
POST /captcha/verify {sitekey, challenge, nonce, signals, trace, hp}BrowserChecks the proof, signals and pointer path. Returns {ok, token}, {ok:false, puzzle} or 403/429.

    
POST /captcha/puzzle {sitekey, id, x, trace | keys}BrowserChecks a puzzle answer and the drag. Returns {ok, token}, a new puzzle, or 403/429.

    
POST /captcha/siteverify {secret, response, remoteip?}Your backendValidates and consumes a token. Has no CORS headers on purpose, since it takes your secret.

    
POST /sites/register {name, origins}DeveloperCreates a site key and secret for the listed website addresses. Limited to 5 per network per day. Turn off with FF_OPEN_SIGNUP=0.

  

  
Keep FF_SECRET stable and shared if you run several instances. Behind a proxy, set TRUST_PROXY=1.
