Protect Your Site in Five Minutes

Get a site key, run one small backend file anywhere Node.js runs, and every visitor passes through the FastFlare check before reaching your site.

How It Works

1 · Visitor clicksYour page shows the "I'm not a robot" box. The click goes to the FastFlare network.
2 · FastFlare decidesLet through, show a quick puzzle, or block, based on the browser's proof-of-work, behaviour and network.
3 · Your backend confirmsThe widget hands the result to your gate, which checks it with FastFlare using your secret.
4 · Through or try againA pass goes to your redirect_to_if_pass page. A fail or block asks the visitor to try again.

The decision is made on the FastFlare server, never in the visitor's browser, and your backend only trusts it after confirming with your secret. A bot that skips the check or forges a pass gets nothing.

2 · Run the Gate

The gate is one file with no packages to install. It needs Node.js 18 or newer and runs on any computer or server: a VPS, Render, Railway, a Raspberry Pi or your own PC.

In PowerShell:

irm https://arthwarrior3201.github.io/FastFlare/kit/fastflare-gate.mjs -OutFile fastflare-gate.mjs
node fastflare-gate.mjs --sitekey=YOUR_SITE_KEY --secret=YOUR_SECRET

In Terminal:

curl -fsSLO https://arthwarrior3201.github.io/FastFlare/kit/fastflare-gate.mjs
node fastflare-gate.mjs --sitekey=YOUR_SITE_KEY --secret=YOUR_SECRET

Open http://localhost:3000 and click the box. When you pass, you land on /welcome, a page only verified visitors can open. Try opening /welcome in a private window first: it sends you back to the check.

3 · Choose Where Visitors Go

OptionWhat it does
--redirect=/dashboardThe redirect_to_if_pass address. Visitors who pass are sent here. Default /welcome (a built-in demo page).
--upstream=http://localhost:8080Put the gate in front of your existing site. Every visitor must pass first; after that, requests go straight through to your site and return to the page they asked for. Your site gets an X-FastFlare-Pass: 1 header.
--port=3000Port the gate listens on.
--pass-minutes=30How long a pass lasts before the visitor is checked again.
--title="Checking your browser"Heading on the check page.
--trust-proxy=1Behind Nginx, Caddy or Cloudflare: read the visitor's address and HTTPS from proxy headers.
--check-ip=1Also require the visitor's address to match the one FastFlare saw. Turn on only when the gate sees real visitor addresses.
--api=https://…Use a different FastFlare server (for example your own).

Every option also works as an environment variable: FF_SITEKEY, FF_SECRET, REDIRECT_TO_IF_PASS, FF_UPSTREAM, PORT, FF_PASS_MINUTES, FF_TITLE, TRUST_PROXY, FF_CHECK_IP, FF_API. Hosting platforms usually set PORT for you.

Going live. Add your real address (for example https://shop.example.com) to the site key's list, serve the gate over HTTPS, and use --trust-proxy=1 if a proxy sits in front of it. Plain http:// addresses are accepted only for localhost.

Use Your Own Backend Instead

Already have a server? Put the widget on your page and point data-verify at your own endpoint:

<script src="https://129-225-87-247.sslip.io/fastflare.js" async defer></script>
<div class="ff-captcha"
     data-sitekey="YOUR_SITE_KEY"
     data-verify="/fastflare/verify"
     data-redirect="/dashboard"></div>

When the visitor passes, the widget sends POST /fastflare/verify with {"token": "…", "redirect": "/dashboard"}. Your endpoint checks the token with FastFlare and answers {"success": true, "redirect": "/dashboard"} to send the visitor through, or {"success": false} (any status) to make the widget say "Could not verify, try again". Only accept same-site paths for redirect.

The check itself is one request from your server:

POST https://129-225-87-247.sslip.io/captcha/siteverify
Content-Type: application/json

{"secret": "YOUR_SECRET", "response": "TOKEN_FROM_THE_WIDGET"}

→ {"success": true, "method": "invisible", "challenge_ts": "…"}
→ {"success": false, "error-codes": ["timeout-or-duplicate"]}

Node.js

import { verifyToken } from './fastflare-gate.mjs';

app.post('/fastflare/verify', express.json(), async (req, res) => {
  const r = await verifyToken(req.body.token, { secret: process.env.FF_SECRET });
  if (!r.success) return res.status(403).json({ success: false, error: r.error });
  req.session.human = true;
  res.json({ success: true, redirect: '/dashboard' });
});

Python (Flask)

import os, requests
from flask import request, session, jsonify

@app.post("/fastflare/verify")
def fastflare_verify():
    r = requests.post("https://129-225-87-247.sslip.io/captcha/siteverify",
                      json={"secret": os.environ["FF_SECRET"], "response": request.json.get("token")},
                      timeout=8).json()
    if not r.get("success"):
        return jsonify(success=False), 403
    session["human"] = True
    return jsonify(success=True, redirect="/dashboard")

PHP

<?php
$in = json_decode(file_get_contents('php://input'), true);

Troubleshooting

SymptomFix
The box says "Could not verify" for everyoneThe page's address is not in the site key's list. The address must match exactly, including http/https and the port. Create a new key with the right addresses.
The gate exits with "FastFlare rejected this secret"The secret does not belong to that site key. Copy both again from step 1.
Passed, but the redirect page sends you backThe browser did not keep the pass cookie: make sure the redirect is on the same site as the gate, and use HTTPS with --trust-proxy=1 behind a proxy.
