Time Server (NTP)

Your own accurate time server. Point Windows, macOS or Linux at it, or read the time for any time zone from a simple web API. About ten minutes from nothing to synced.

Precise

Combines several of the internet's most trusted time sources and compensates for network delay, so results are typically within a few milliseconds.

Always Current

The clock is tracked continuously in the background. Every request is answered instantly, with no lookup delay.

Lightweight

One small Node process. Runs comfortably on a 1 GB free-tier cloud server.

What You Need

  • A Linux server (Ubuntu or Debian) with a public IP address. A free Oracle Cloud server works; steps are below.
  • Inbound UDP 123 (time) and TCP 8787 (web API) allowed to that server.

Set Up the Server

  1. Create a server Use any Ubuntu or Debian server. On Oracle Cloud Always Free: Compute → Instances → Create instance, image Canonical Ubuntu 22.04 Minimal, shape VM.Standard.E2.1.Micro, let it create a new public network, and download the SSH key it generates. When it shows Running, copy its Public IP address.
  2. Allow the two ports in the cloud firewall On Oracle Cloud: open the instance, click its subnet, then Default Security List → Add Ingress Rules. Add two rules with source 0.0.0.0/0:
    ProtocolDestination port
    UDP123
    TCP8787
  3. Connect to the server 
    ssh -i path/to/your-key.key ubuntu@YOUR.SERVER.IP
    On Windows, first run icacls "path\to\your-key.key" /inheritance:r /grant:r "%USERNAME%:R" so SSH accepts the key.
  4. Run the installer One command installs everything: Node.js, a 4 GB swap file on small servers, the server's own firewall rules, and a background service that starts on boot. 
    curl -fsSL https://raw.githubusercontent.com/ArthWarrior3201/FastFlare/main/deploy/install.sh | sudo bash
    When it finishes it prints your server's address and the exact commands for Windows.
  5. Check that it works Open this in a browser (use your IP): 
    http://YOUR.SERVER.IP:8787/time?tz=Asia/Kolkata
    The reply should contain "synced": true. If the page does not load, recheck step 2.

Run the Server on macOS or Windows Instead

No cloud server? Any always-on computer on your network can host FastFlare. Other devices on the same network then use that computer's address as their time server.

macOS

curl -fsSL https://raw.githubusercontent.com/ArthWarrior3201/FastFlare/main/deploy/install.command | bash

Or download install.command and double-click it (if macOS blocks it, run chmod +x install.command first or use bash install.command). It installs Node.js if needed and sets up a background service that starts at boot. If macOS asks about incoming connections for "node", choose Allow.

Windows

Open PowerShell as administrator and run:

irm https://raw.githubusercontent.com/ArthWarrior3201/FastFlare/main/deploy/install.ps1 | iex

Or download install.cmd and double-click it. It installs Node.js if needed, opens the firewall ports and starts FastFlare at every boot. To make a Windows PC take its time from an existing FastFlare server in one step, run install.cmd -Client SERVER.IP. To remove FastFlare: install.cmd -Uninstall.

The PC running FastFlare cannot use itself as its own time source; point your other devices at its address instead.

Point Your Devices at It

Windows

Open Command Prompt as administrator and run (replace the IP):

w32tm /config /manualpeerlist:"YOUR.SERVER.IP,0x8" /syncfromflags:manual /reliable:no /update
net stop w32time && net start w32time
w32tm /resync /force

Confirm with w32tm /query /status (the source should be your server) and w32tm /stripchart /computer:YOUR.SERVER.IP /samples:5 /dataonly, which prints the difference between your PC and the server in seconds. To go back to Windows' default source later: w32tm /config /manualpeerlist:"time.windows.com,0x8" /syncfromflags:manual /update, then restart the Windows Time service.

macOS

System Settings → General → Date & Time → Source → Set, then enter your server's IP address. Or from Terminal: sudo systemsetup -setnetworktimeserver YOUR.SERVER.IP.

Linux

With chrony, add server YOUR.SERVER.IP iburst to /etc/chrony/chrony.conf and run sudo systemctl restart chrony. With systemd-timesyncd, set NTP=YOUR.SERVER.IP in /etc/systemd/timesyncd.conf and run sudo systemctl restart systemd-timesyncd.

Web API

GET /time?tz=Asia/Kolkata

{
  "unixMs": 1795347120123,
  "utc": "2026-11-22T09:32:00.123Z",
  "timeZone": "Asia/Kolkata",
  "abbreviation": "GMT+5:30",
  "offsetMinutes": 330,
  "local": "2026-11-22T15:02:00.123+05:30",
  "synced": true,
  "uncertaintyMs": 4.3
}

tz is any IANA time zone name (America/New_York, Europe/London, UTC) and defaults to UTC. uncertaintyMs is the current error bound. Add ?fresh=1 to trigger an extra sync before answering (limited to one every 2 seconds). GET /time/status reports sync health.

// JavaScript
const t = await (await fetch('http://YOUR.SERVER.IP:8787/time?tz=Asia/Kolkata')).json();
console.log(t.local);

No UDP? Use a Web Host

Some hosts (Render, Vercel and similar) only provide HTTP, which Windows cannot use as a time source directly. Deploy FastFlare there (the repository includes a render.yaml) and sync Windows over HTTPS instead. In an administrator PowerShell:

powershell -ExecutionPolicy Bypass -File windows-sync.ps1 -Server https://your-app.onrender.com -Install

The script, tools/windows-sync.ps1, corrects the clock every 15 minutes. Expect tens of milliseconds of accuracy with this method, compared with a few using the server above.

Updating

Run the installer command again. It updates the code, keeps your settings and restarts the service. Logs: sudo journalctl -u fastflare -f.

Settings

Stored in /etc/fastflare.env on the server. Restart with sudo systemctl restart fastflare after editing.

VariableDefaultMeaning
FF_TIME_PROVIDERSGoogle, Apple, Windows, Cloudflare, NIST, pool.ntp.orgComma-separated list of upstream NTP hosts (host or host:port).
FF_TIME_POLL_MS32000How often the clock is re-checked in the background.
FF_TIME_TOLERANCE_MS50Maximum disagreement between sources before one is set aside for that check.
NTP_PORT123UDP port for the time server. Set FF_NTP=0 to turn the NTP server off and keep the web API only.
PORT8787Web API port.

Troubleshooting

ProblemFix
The web API does not loadCheck the TCP 8787 rule in your cloud firewall, then sudo systemctl status fastflare.
"synced": false for more than a minuteThe server cannot reach public time servers. Check outbound UDP 123 and run sudo journalctl -u fastflare -n 50.
Windows: "no time data available" or the stripchart times outCheck the UDP 123 rule in your cloud firewall. Some office or school networks block NTP; try another network.
Installer says port 123 is busyAnother time service owns it. Stop it (sudo systemctl disable --now chrony) and restart FastFlare.
